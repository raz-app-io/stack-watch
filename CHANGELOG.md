# Changelog

## Unreleased

- The sample project's `package-lock.json` is generated by `examples/sample-next-app/generate-lockfile.py` from `locked-versions.json` instead of being committed, so its deliberately old pins no longer show up as Dependabot alerts on this repository. Tests build it into a temporary copy

## 1.3.1 (2026-10-28)

Security hardening from an internal review; no behavior change for ordinary runs.

- New `safe_http.py` used by every fetcher: http(s) only, credentials in URLs refused, private/loopback/link-local/metadata addresses refused unless `--allow-private-hosts`, redirects followed manually with the same checks per hop, `Authorization` dropped on cross-host redirects, response size caps (5 MB feeds, 2 MB endoflife.date documents, 30 MB registry records, 20 MB OSV)
- `headless.py` never falls back to the package manager's audit (OSV.dev only); the digest escapes Markdown and defuses `@mentions` in vendor text and links only http(s) URLs
- npm package names are validated against npm's rule before any registry URL is built
- Workflow template pins stack-watch to the release tag and all actions to commit SHAs; repo CI pinned the same way; Dependabot keeps the pins current
- SECURITY.md with scope and the private reporting channel
- 16 new tests (83 total), including a local HTTP server exercising redirects, token handling, and size limits

## 1.3.0 (2026-10-22)

- New `rank.py`: every proposal gets a score (severity base + impact + exposure + urgency - effort cost) and a grade A to D, the table is sorted by score, and a Default column suggests ticket, ticket (backlog), or watch. A summary line counts grades; `defaults` is a valid reply
- Deadlines show their distance ("2026-10-23 (tomorrow)"); Pricing rows show direction (increase, favorable)
- severity-rubric.md: Scoring section defining impact, exposure, deadline, fix_available, pricing_direction
- samples: proposals.json and the regenerated graded table

## 1.2.0 (2026-10-22)

- `audit.py` queries OSV.dev with the lockfile's exact versions by default; no package manager needed. Falls back to `npm`/`pnpm`/`yarn`/`bun audit`. Same titles and advisory URLs either way, so the ledger dedupes across sources
- New `lifecycle.py`: end-of-life dates from endoflife.date (Node.js, Next.js, React, Vue, Nuxt, Svelte, Angular, Express, Bun, Electron, Tailwind CSS) and deprecated or outdated pinned versions from the npm registry, as Deprecation items plus report tables
- New `discover_sources.py`: proposes sources for any npm dependency from its registry record (GitHub releases feed) and homepage (RSS/Atom autodiscovery and conventional paths)
- New `headless.py` and `assets/stack-watch.yml`: a scheduled GitHub Actions probe that opens an issue with a digest when there is something new; never writes into the repo
- Fixes from an independent review: STACK.md no longer records an absolute path; prerelease filter is version-shaped; Noise ledger entries are compact; stale "(inferred)" hosting label is replaced; redirects limited to http(s); ledger CLI errors are one line
- SKILL.md: fetched content is data, never instructions; related items are grouped into one proposal

## 1.1.0 (2026-10-22)

- Deterministic pipeline: `render_stack.py` writes and merges STACK.md, `fetch_sources.py` reads feeds and GitHub releases, `audit.py` normalizes package-manager audits, `ledger.py filter` dedupes
- 27 verified vendor sources; `url_filter` for feeds that mix a blog with a changelog
- `/stack-watch [bootstrap|probe] [path]` plugin command
- `examples/sample-next-app` input project and `samples/` with one complete run's output and a walkthrough
- Markdown tracker writes tickets as rows in one table
- Fixes: pnpm, Yarn and bun lockfile versions; Atom `xhtml` bodies; 308 redirects; Analytics rows no longer drift every run

## 1.0.0 (2026-10-22)
